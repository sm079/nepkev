This is Kev-0.8B fine-tuned for Nepali support routing. It does not write an answer. You give it a state (the customer's message) and typed questions; each question is one forward pass that scores every option you offered, so the result is a probability per option. It can't invent a category or return broken JSON.

  • choice which team gets the ticket (11 categories per service)
  • noul does the agent have to ask a follow-up first?
  • 0 output tokens. Everything runs on this device.

How it works

    
    
      
  1. Every question becomes one token row: <state> message <q> instruction <opt> option </opt> … <decide>. The instructions and option descriptions are English; only the message is Nepali.
    2. 
      
  2. The backbone (Qwen3.5-0.8B with the fine-tuned LoRA merged in, exported to ONNX) runs the row once. No tokens are generated.
    3. 
      
  3. A pointer head compares the hidden state at <decide> with the hidden state at every </opt>. A softmax over those scores, at the calibration temperature, gives the probabilities.
